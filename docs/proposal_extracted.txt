1. Executive summary and research motivation
This proposal evaluates whether topological descriptions of Bitcoin transaction networks, specifically Betti numbers
and persistent homology, add measurable value to anti-money-laundering (AML) and illicit transaction classification.
The work is deliberately designed around out-of-time evaluation, structural confounding controls, dataset-specific
graph construction and publicly reproducible experiments.
Primary research question: Do persistent topological signatures add statistically significant and operationally
useful predictive information beyond transaction attributes, conventional graph statistics and established graph
neural networks?
Primary proposed title: TopoAML: Persistent Homology-Guided Graph Learning for Leakage-Free Bitcoin
Anti-Money Laundering.
Alternative titles: BettiTrace: Multiscale Topological Signatures for Explainable Illicit Transaction Detection in
Bitcoin Networks; TopoFin: A Persistent Homology Framework for Detecting Financial Crime Patterns in Blockchain
Transaction Networks.
2. Objectives, hypotheses and novelty tests
ID Hypothesis / question Falsifiable evidence
H1 Licit and illicit network neighborhoods exhibit differing topological signatures.
Label-conditioned distributions and paired tests, with size/density controls.
H2 Static Betti features improve AML detection. Matched classifier with and without Betti features.
H3 Persistent homology improves on static Betti features.
Incremental PR-AUC with uncertainty intervals.
H4 Topology helps future-period generalization. Locked later-time test on Elliptic++.
H5 Topology supports external subgraph classification. Separate Elliptic2 test; do not equate different label granularity.
H6 Improvements are robust and interpretable. Radius/threshold perturbation, runtime and case-level review.
Novelty must be established against current 2024-2026 literature. Adding two Betti counts to a GNN is likely
insufficient by itself. Potentially defensible contributions include a time-respecting financial graph filtration,
directed-versus-undirected topological comparison, independent financial validation, and rigorous evidence of added
value beyond classical structural features.

4. Data integrity, leakage prevention and split policy
• Maintain immutable raw files and preserve original transaction IDs, edge direction, time step and any unknown
class labels.
• Suggested Elliptic++ time split: steps 1-30 train; 31-39 validation; 40-49 test. This is a proposed protocol, not a
claimed official baseline. Publish lists of node IDs and per-class counts.
• No label-derived features, future transactions, training-on-test graph embeddings, target encoding from held-out
labels, or threshold tuning on test data.
• Explicitly state whether training-time message passing uses only historical observed nodes/edges (strict inductive)
or transductive observed topology. Report any allowed cross-boundary connectivity.
• Fit normalizers, feature selectors, resampling rules and imputation on training data only. Keep unknown-label
vertices distinct from negative examples.
The strict historical setting should reconstruct a graph snapshot at each decision time. Historical topology is
permissible; future transactions and labels are not. Cross-dataset validation may require retraining with
corresponding graph features rather than direct feature transfer.
5. Graph formulations and topology
5.1 Directed finance graph
At an observation time t, let G_t=(V_t,E_t,X_t) denote transactions, observed transfer-dependency edges and node
attributes. Bitcoin transaction-dependency graphs are normally directed acyclic, but their undirected projections may
contain cycles. An undirected cycle is not proof of funds cycling or money laundering.
5.2 Local neighborhoods and graph cycle rank
Construct target-centered neighborhoods with k in {1,2,3}; use a validation-set decision for the preferred scale. For
an undirected graph with V nodes, E edges, and C connected components, beta_0=C and beta_1=E-V+C. For a
graph treated as a one-dimensional complex, beta_2=0. Graph size, edge count and component count must be
included as controls because cycle rank is determined by these counts.
5.3 Persistent topology
Define a nested family of simplicial complexes K(a_1) subset K(a_2) subset ... subset K(a_m). For homological
dimension k, beta_k(a)=rank H_k(K(a)). Record finite persistence intervals (birth b_i, death d_i), lifetimes d_i-b_i,
maximum/mean lifetime, persistence entropy, Betti curves and vectorized persistence images or landscapes. Clearly
specify treatment of essential/infinite intervals.
Graph cycles in a one-dimensional complex and H1 of the associated flag/clique complex differ: filling a triangle
removes that triangle as a 1-dimensional homology class. H2 can only be meaningfully claimed when the chosen
simplicial construction supports higher-dimensional cells. Do not expect nonzero H2 by default.
5.4 Filtration alternatives
Filtration How to implement Potential pitfall
Structural-distance Reveal subgraph relationships by well-defined graph-distance threshold.
Prove nestedness; graph shortest paths can obscure financial direction.
Edge-weight Reveal edges by decreasing similarity or increasing distance, with consistent simplex filtration values.
Do not claim financial transfer amounts if only derived structural weights exist.
Temporal Add only edges/nodes visible by each timestamp, using synchronized historical snapshots.
No future graph information or post-event exposure.
Directed path homology Research path-homology representation retaining directed edges.
Mathematically and computationally more involved; benchmark separately.
6. Models and baselines
First establish a simple fusion baseline z_v=[x_v || s_v || T_v || h_v], where x_v are transaction features, s_v
conventional structural features, T_v topological descriptors and h_v learned GraphSAGE/GAT embeddings. A
multilayer perceptron predicts illicit probability. The proposed advanced model uses a learnable topological encoder
and gated feature fusion; only introduce it after simple topology is informative.
Group Models / comparisons
Tabular Logistic regression, random forest, XGBoost
Graph GraphSAGE, GAT
Structural controls Tabular + node degree, edge count, density, clustering, triangles, component size, cycle rank
Static topology XGBoost + static Betti; GAT + static Betti
Persistent topology XGBoost + persistence; GAT + persistence
Advanced TopoAML gated fusion vs naive feature concatenation
Use the same split, observed data, training budget and selection objective wherever possible. Report parameter
counts and inference latency. Separate task-specific baselines for Elliptic2 subgraph labels from transaction-node
baselines.
7. Seven required experiments and statistical design
ID Protocol Outputs
E1 Topological profiling of labels with structural confounder adjustment. Density plots; persistence diagrams; effect sizes.
E2 Ten-model comparison, same test protocol. PR-AUC; ROC-AUC; precision; recall; F1.
E3 Remove static beta, persistent descriptors, encoder, gating. Ablation deltas with intervals.
E4 Evaluate later times without tuning. Temporal performance and drift plots.
E5 Elliptic2 subgraph task as external validation. Independent task results and limitations.
E6 k-radius, filtration choice, perturbation, seeds. Sensitivity and robustness plots.
ID Protocol Outputs
E7 Runtime, memory, throughput on bounded graphs. Complexity and deployment practicality.
Primary metric: illicit-class area under the precision-recall curve (PR-AUC). Also report ROC-AUC, recall at a fixed
false-positive rate, precision at investigation budget (top-K), calibration, model size, peak RAM, GPU memory and
elapsed time. Evaluate at least five random seeds, with uncertainty intervals. For paired differences use appropriate
resampling or paired tests at the independent evaluation unit; account for graph dependence.
Do not claim statistical significance solely because one run outperforms another. Pre-register the primary objective
and major comparisons where feasible. Failure to improve over degree/density/cycle-rank baselines is scientifically
informative and should be disclosed.

9. Expected deliverables and success criteria
The expected outputs are a checked dataset manifest, a documented topological feature pipeline, reusable graph
learning code, full ablation tables, timing studies, reproducibility package and journal manuscript. No numerical
success threshold is assumed a priori. The strongest paper would establish exactly when topology is useful and
when it adds no value, with rigorous controls.

13. Final evidence and submission checklist
• No held-out labels or future edges enter feature extraction.
• All topology computations reproduce known mathematical test cases.
• Structural feature controls are compared against topological features.
• The primary performance comparison has confidence intervals.
• Elliptic2 is presented as a distinct subgraph task, not an identical dataset replication.
• All plots and tables are regenerated from published scripts.
• Every reference DOI, full metadata and Scopus status is independently verified.
• Current Scopus quartile/category, fees and journal scope are reconfirmed before submission.
Conclusion: TopoAML is a testable proposal, not yet a validated result. Its core value is the planned combination of
principled topology, time-respecting graph evidence, matched baselines and independently reproducible financial
experiments.
